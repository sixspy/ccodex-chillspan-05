## 定稿口径：甲路径（二选一已定，第三路不许，双口径不得并行）

**任一端点已封代（目标端或来源端批次 `status='已封批'`），正式血缘边零增并拒收（HTTP 409）。**

乙路径（影子血缘草稿 → 代对齐晋升 / 否则回滚）未选用：跨代不落地任何形式的影子边，
未获接纳的连边尝试一律不得计入正式血统。双口径并行会产生封代外伪血统，禁止。

## 配套规矩

1. **血缘锁**：同一对端点增边须先抢 `lineage:{from_batch_id}:{to_batch_id}` 锁；
   后到留争用痕（`contention_log` + 审计 `lineage_contention`），不落边。
2. **偏航**：纪要缺失、未当班封死或路径被改（含第三路），一切落边记血缘偏航
   （`lineage_deviations` + 审计 `血缘偏航`）并拒写。
3. **代快照**：正式边落库定格两端当时代（`from_generation` / `to_generation`），
   审计按快照追溯，不按批次现世代。
4. **封批定格**：封批清单 manifest 嵌入当时正式血缘快照。
5. **温谱闸口**：批次涉跨代伪连（正式边任一端落边时已封代）禁止导出温谱。
6. **五页同源**：血缘页、封批页、批次页、温谱页、仓间页同库同 API 口径；
   对账端点 `GET /api/lineage/reconcile` 全量扫描伪连。
